# digest

A monorepo for **digest**, an MCP server that fetches files into a structured
artefact store, converts supported formats (markdown, HTML) to a typed section
tree, and serves content through four tools: `fetch_file`, `read_document`,
`read_section`, and `write_section`. HTML pages render in a stealth headless
browser (CloakBrowser, in Docker) when the pipeline rule requires it; markdown
and plain downloads run entirely in-process with no Docker.

See **[app/digest/README.md](app/digest/README.md)** for
installation, configuration, tools, and usage.

## Layout

This is a pnpm workspace (`app/*` + `packages/*`):

| Package | Purpose |
|---------|---------|
| [`app/digest`](app/digest) | `@mfassaie/digest` -- the published bin: MCP entry point and admin CLI, bundled with esbuild. Its `docker/` payload is generated by the build. |
| [`packages/shared`](packages/shared) | `@digest/shared` -- host-side core: settings engine, artefact store, markdown engine (fold/splice/sticky ids), fetch (local HTTP + file), SWR freshness, chunking, HTML adapter, logging. |
| [`packages/mcp-server`](packages/mcp-server) | `@digest/mcp-server` -- MCP tool definitions (one module per tool), dispatch handlers and response formatting. |
| [`packages/docker`](packages/docker) | `@digest/docker` -- host-side container lifecycle + HTTP client, the in-image fetch/convert service with instruction protocol, and the image build context. |
| [`packages/e2e`](packages/e2e) | `@digest/e2e` -- end-to-end tests. No-Docker subset: `verify-dev`, `verify-store`, `verify-settings`. Docker-dependent: `e2e`, `verify-docroot`. |
| [`packages/tooling-evals`](packages/tooling-evals) | `@digest/tooling-evals` -- the HTML-to-Markdown converter eval harness (defuddle chosen, ADR-006). |

```sh
pnpm install
pnpm build        # build all packages (docker context, then the app bundle)
pnpm test         # all package tests + no-Docker e2e
```

Key design decisions are noted in code comments by ADR number (converter
choice, container engine, per-type pipelines, artefact model).
